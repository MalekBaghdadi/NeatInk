## Session 14 (2026-10-30, cloud session): v1.12.0, lecture recording and guided tours

Same branch `claude/autocorrect-arrows-join` (equal to `main` at 1.11.0). Mariam had not tested 1.11 yet. The owner asked for (1) recording, "two options mainly: just replay the recording, or replay with the notes taken", "understandable for non-tech people", with the whole menu (stop and so on), integrated the best way; (2) a step-by-step guide of each section (library, PDF, notes) that highlights the buttons and says what each does, plus tooltips on long press or pen hover; then "build and push to GitHub".
- **Native recorder** (`AudioPlugin.kt`, channel `neatink/audio`; `RecordingService.kt`): `MediaRecorder` writing AAC in an ADTS stream (`.aac`, 64 kbit/s, mono, 44.1 kHz, ~29 MB per hour): ADTS has no index to finalise, so a file cut short by the app being killed still plays up to the end. Pause/resume (API 24+). A foreground service of type microphone (notification "Recording your lecture", channel "Recording", low importance; 6-hour partial wake lock; START_NOT_STICKY) keeps it going with the screen off or in another app. The recorder lives in a Kotlin singleton, so it outlives the Flutter screen; a new start of the app takes it back (`RecordingController.reattach`, prefs key `activeRecording`). Playback: `MediaPlayer` (seek `SEEK_CLOSEST`, speed via `PlaybackParams`). Permissions asked on first use: `RECORD_AUDIO`, and `POST_NOTIFICATIONS` on API 33+; manifest adds `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MICROPHONE`, `WAKE_LOCK`. No INTERNET.
- **Data**: `<notebook>/audio/<id>.aac` + `audio/recordings.json` (`{"version":1,"recordings":[{id,title,file,createdAt,spans:[{wallStart,wallEnd,audioStart}],inProgress}]}`, `document/recording.dart`, `storage/recording_store.dart`, atomic writes, one queue per notebook). Spans map the wall clock to the sound and back (one span per stretch between pauses): a note written during a pause belongs where the sound goes on. The timeline is saved at start/pause/resume/stop and every 10 s, so a recording cut short keeps all but the last seconds (`finishInterrupted`, `inProgress`). Per-note times: `Stroke.writtenAt` (JSON `at`, ms since the epoch, set by the pen/highlighter/shape tools, kept by lasso moves, pixel-eraser pieces and copies) and `TextItem.times` (`[{"start", "at"}]`: where in the text each converted line starts and when its ink was written; `remapTimes` moves them with edits, Auto appends a merged line's times). Typed text without times (typed by hand, older notes) shows at once. Recordings travel with the notebook folder: backups (`notebooks/<id>/**`), Trash, duplicate (`_copyRecordings`).
- **UI** (`integrations/recordings/`, `features/recording/`): a microphone button at the top of a notebook ("Record a lecture"); the first time, a short explanation (what happens, Allow the microphone, it keeps recording in other apps, tap Stop at the end, how to listen) with Start recording / Not now; while recording a red bar under the tools: pulsing dot, time, level meter, Pause / Go on, Stop. Microphone refused -> how to allow it (Settings › Apps › Mariam's Notes › Permissions › Microphone). Leaving the notebook while recording asks: Stay here / Stop and save / Keep recording (a red banner at the top of the library: Open notebook, Stop). A headphones button with the count opens the recordings sheet: one card per recording (name "Lecture, 30 Oct, 09:05", length), **Play** and **Play with notes** (greyed when no notes were written during it), ⋮ Rename / Delete (the notes stay). The player bar: play/pause, back/ahead 10 s, slider, time, speed (1, 1.25, 1.5, 2, 0.75x), "Notes as written" switch, close.
- **Play with notes** (`PlaybackController implements InkReveal`, `canvas/ink_reveal.dart`): notes written after the sound's position are painted at `aheadOpacity` 0.16 (strokes in `page_painting.dart`, typed text per line from `TextItem.times` via `layoutTextItem(faintFrom:)`); only pages whose notes change are repainted; the view scrolls to the newest note as it appears (`follow`); a pen or finger tap on a note plays from `leadInMs` 1.5 s before it was written and draws nothing.
- **Guided tours** (`features/tour/`): `showTour` dims the screen with a lit, ringed cut-out around a widget found by its `ValueKey<String>` (prefix keys light a group: all pen colours) and a card (title, what it does, "N of M", Skip tour / Back / Next; a tap anywhere is Next). Steps whose button is not on screen are left out (no recordings yet -> no "Recordings" step). Three tours: library (8 cards), notebook (21), PDF notebook (+2). Each starts by itself once, when its screen is on top and the screens above have finished closing (`startTourWhenOnTop` checks after each frame: the first-run Tips screen is a fullscreen dialog, which does not move the library route's secondary animation, so that could not be listened to); flags `tourSeen.<name>` in prefs, marked before showing. Notebook ⋮ › Show me around; Settings › About › Show me around again (`TourMemory.resetAll`). `autoToursProvider` is on in `main.dart`, off in tests. The overlay measures the target outside build (walking the element tree during build asserts).
- **Tooltips**: every tool button says what it does (`EditorTool.hint`, "Lasso: draw a loop around notes to move, copy, convert or restyle them"); the library buttons, quick page navigation and the recording buttons got plain-language tooltips. Theme: 500 ms wait, 3.5 s shown, inverse-surface colours at 14.5 pt. Flutter shows tooltips on a long press and on mouse/stylus hover (the M-Pencil's hover arrives as a hover pointer event, if EMUI reports it).
- **Tips**: two new cards (Record a lecture; What does this button do?).
- Verified here: analyze clean, 1555 pass / 2 skipped (recording model 12, recordings UI 7, tour 4, plus the times in Auto); recording UI and tour checked on screenshots; local release build (Kotlin compiles). ### Session 8, part 3: Scribble to delete and the 1.6.0 release

- **Scribble to delete** (owner request, like the iPad): a pen stroke that goes back and forth over handwriting or typed text deletes what it covers, in one undo step "Scribble to delete"; the scribble itself is not added. Settings > Writing > "Scribble to delete" (`AppSettings.scribbleToDelete`, JSON key `scribbleToDelete`, on by default; backups carry it) and a tip.
  - Shape (`tools/scribble.dart`, `isScribbleShape`): principal axis of the points; back and forth along it (>= 4 reversals with hysteresis, swings >= 30% of its length, path >= 2.5 x length) or zig-zag across it (>= 5 turns, swings >= 60% of its height, path >= 1.8 x length); at least 8 pt long. Letters like "M", "ll" or cursive "mm" pass the shape test too.
  - So what counts is the content (`planScribble`): strokes with >= 60% of their points in the scribble's bounds (+2 pt), or covered over >= 60% of their width and >= 35% of their height (a tall `l` crossed out through its middle); typed words whose box is covered the same way (laid out with `layoutTextItem`). The covered things must fill >= 30% of the scribble's area, else it is ink (writing over a stray dot, a scribble on empty paper). A closed outline around the whole scribble (a hand-drawn circle, a snapped rectangle/ellipse/triangle) is kept: shading inside a drawn cell does not erase the cell. Long lines crossing it stay.
  - Typed text loses only the covered words (`withoutWords` keeps a line break if one was there), the box is re-measured, and an emptied box is removed. Numbers: `ToolConfig.scribble*`.

### Rules that kept parallel agents from colliding

- Each agent checks only its own files with `flutter analyze <paths>` and runs only its own tests.
- Partial work from an agent that was cut off is continued, not rewritten: read what exists first.
